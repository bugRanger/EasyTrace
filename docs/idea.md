## 1. Мотивация

Мотивацией для написания этого проекта послужили проблемы с нагрузкой на память и GC.

Единственное предлагаемое решение "из коробки"
это [OpenTelemetry .NET](https://github.com/open-telemetry/opentelemetry-dotnet),
которое может создавать серьезную нагрузку на GC. Если ваше приложение обрабатывает тысячи или сотни тысяч
микро-запросов в
секунду (например, высоконагруженное API),
то создание [Activity](https://learn.microsoft.com/ru-ru/dotnet/api/system.diagnostics.activity?view=net-9.0)
превращается в огромный поток короткоживущих объектов.
Это заставляет GC работать чаще (Gen 0 коллекции), что потребляет ресурсы процессора и портит замеры.

## 3. Предлагаемое решение

Для снижения нагрузки на GC следует прибегать к повторному использованию Activity, но
в [System.Diagnostics.Activity](https://learn.microsoft.com/ru-ru/dotnet/api/system.diagnostics.activity?view=net-9.0)
нет сброса и от него следует отказаться.

Задействовать [OpenTelemetry .NET](https://github.com/open-telemetry/opentelemetry-dotnet) для экспорта не получиться,
т.к. сильно завязан
на [System.Diagnostics.Activity](https://learn.microsoft.com/ru-ru/dotnet/api/system.diagnostics.activity?view=net-9.0)
и не имеет АПИ для замены этого компонента на свой аналог.

### Цели

1. Написать аналог Activity с возможностью хранением его в пуле;
2. Написать экспортеры для аналога Activity.
